## **CentOS7 PTP 精准对时（ptp4l + phc2sys）实践**

------

适用系统：CentOS 7.4–7.9

适用网卡：支持 PTP 的万兆/百兆/光口 NIC（如 Intel i40e、ixgbe、Mellanox、Solarflare）

下面以 **CentOS 7.6 + linuxptp（ptp4l + phc2sys）** 为核心， **从零实践配置 PTP 精准对时**，并使用 **p10p1**  (对应 PHC 设备：**/dev/ptp0**, )作为接入时钟源的网卡。

------


# **1. 基本原理（务必理解）**

精准对时（PTP）依赖三个关键角色：

1. **Grandmaster（上级时钟源）**：提供最精准的时间 （卫星**原子钟**或交易所**PTP授时服务**）。

2. **Slave（本机）**：从 Grandmaster 学时间。

3. **PHC（网卡硬件时钟）**：高速、精确，位于 NIC 上。

4. **System Clock（系统时钟）**：Linux 系统本身的 clock。

------

PTP（1588v2）分两步完成：

## **① ptp4l：让 PHC（网卡硬件时钟） 与 Grandmaster 对齐**

- PHC 通常运行在 **TAI 时间**
- 如果 ptp4l 处于 **SLAVE** 状态，则 PHC 被不断校准，精度可达纳秒级



## **② phc2sys：让 Linux 系统时钟 与 PHC 同步**

- 系统时钟（CLOCK_REALTIME）为 **UTC**

- PHC（TAI）与 UTC 永远差 **currentUtcOffset = 37s**

  （这是闰秒累计差，不是对时错误）

因此出现：

```
PHC - CLOCK_REALTIME == -37 秒
```

是正常的 **UTC vs TAI** 行为。

真正的同步精度是：

**sub-second offset（几十 ns ~ 几百 ns）**

------



# **2. 前置检查**

## **检查网卡是否支持 PTP 与硬件时间戳**

```
ethtool -T p10p1
```

确保包含：

- PTP Hardware Clock: 0
- SOF_TIMESTAMPING_TX_HARDWARE
- SOF_TIMESTAMPING_RX_HARDWARE

检查 PHC：

```
ls -l /sys/class/net/p10p1/device/ptp
```

输出应有：

```
ptp0 → /dev/ptp0
```

------



# **3. 配置 ptp4l（同步 PHC）**

创建配置：

```
/etc/ptp4l.conf
```

内容：

```
[global]
time_stamping            hardware
delay_mechanism          E2E
tx_timestamp_timeout     40
summary_interval         0

[interface "p10p1"]
```

手动启动测试：

```
ptp4l -f /etc/ptp4l.conf -i p10p1 -m
```

你应看到：

```
port 1: SLAVE
master offset     xxx ns
```

当处于 **SLAVE** 且 offset 在微秒/纳秒级波动 → PHC 已与 Grandmaster 同步。

------



# **4. 配置 phc2sys（同步系统时钟）**

正式建议使用 PHC 设备：

```
phc2sys -s /dev/ptp0 -w -m
```

输出类似：

```
sys offset      50 ns
```

说明系统钟（UTC）已与 PHC（TAI）同步到 ns 级。

------



# **5. 开机自启（可选）**

## **ptp4l**

创建：

```
/etc/systemd/system/ptp4l.service
```

内容：

```
[Unit]
Description=PTP Hardware Clock Synchronization (ptp4l)

[Service]
ExecStart=/usr/sbin/ptp4l -f /etc/ptp4l.conf -i p10p1
Restart=always

[Install]
WantedBy=multi-user.target
```

启用：

```
systemctl enable --now ptp4l
```



## **phc2sys**

```
/etc/systemd/system/phc2sys.service
```

内容：

```
[Unit]
Description=Synchronize System Clock to PHC

[Service]
ExecStart=/usr/sbin/phc2sys -s /dev/ptp0 -w
Restart=always

[Install]
WantedBy=multi-user.target
```

启用：

```
systemctl enable --now phc2sys
```

------



# **6. 验证与检查（关键）**



## **① 验证系统对时精度（主要指标）**

```
phc2sys -s /dev/ptp0 -w -m
```

观察：

```
sys offset      20 ~ 500 ns
```

表示系统时钟与 PHC 对齐正常。

------



## **② 验证 PHC 与系统钟的差（不要被秒级差迷惑）**

```
phc_ctl /dev/ptp0 cmp
```

可能输出：

```
offset from CLOCK_REALTIME is -36999999942ns
```

这是因为：

- PHC 使用 TAI
- 系统时钟使用 UTC
- currentUtcOffset = 37

**这是正常的，不是故障。**

------



## **③ 验证 Grandmaster 偏差**

```
pmc -u -b 0 'GET PORT_DATA_SET'
```

关注：

```
offsetFromMaster
meanPathDelay
```

offsetFromMaster 应在：

- **几十 ns～几百 ns（优秀）**
- < 1 µs（可接受）

------



## **④ 验证当前 UTC 偏移（闰秒）**

```
pmc -u -b 0 'GET TIME_PROPERTIES_DATA_SET'
```

你看到：

```
currentUtcOffset = 37
```

说明 TAI-UTC = 37 秒，这是 2025 年正常值。

------



# **7. 常见问题与答案（非常重要）**

### **✔ Q1：为什么 PHC 与系统钟差 37 秒？**

因为：

- PHC = TAI
- 系统钟 = UTC
- TAI–UTC = 37 秒（闰秒累计）

完全正常。

------



### **✔ Q2：同步是否成功的真正判断是什么？**

看：

- phc2sys sys offset（纳秒级）
- pmc offsetFromMaster（纳秒级）

不要看 phc_ctl cmp 的秒级差值。

------



### **✔ Q3：为什么 date 显示正确？**

Linux 系统钟运行在 **UTC**，phc2sys 会保持它正确，不会变成 TAI 时间。

------



# **8. 最终结论（TL;DR）**

- 你的系统并没有异常
- PHC 与 system clock 相差 37 秒是 TAI vs UTC 的必然结果
- 真正的对时精度要看：
  - phc2sys sys offset
  - pmc offsetFromMaster
- 如果 offset 是 ns/µs 级，你的 PTP 部署已经成功
